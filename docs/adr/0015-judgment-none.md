# ADR-0015: Jev が「該当なし」と答えた記事は、該当なしとして保存して判定済みにする

- 状態: 採用
- 日付: 2026-10-20

<!-- constrained-by ./0011-ai-scope.md -->

## 背景

記事ごとの判定（`src/jobs/judge.ts`）は、ジャンルの選択肢に「該当なし」を加えて Jev に問う。TASK-23 までの実装は「該当なし」の確率を捨て、残りのジャンルの確率だけを `judgments` に保存していた。そのため「該当なし 0.9、tech 0.05」の記事が tech 0.05 として判定済みになり、記事一覧で tech に分類されていた。

記事ごとに判定するフィードは雑多なサイトなので、どのジャンルにも当てはまらない記事が多数派になる。

## 決定

- **「該当なし」も他のジャンルと同じく、確率を `judgments` に保存する。** `judgments.topic` には、ジャンルの語彙に加えて予約値「該当なし」が入る。
- 「該当なし」が最大の記事は、記事一覧でジャンルが「該当なし」の記事として扱う。include の絞り込みでは隠れ、exclude だけ・絞り込み無しなら表示する。記事単位の判定はサイト単位のジャンルより優先する（ADR-0011）ので、フィードにジャンル tech が付いていても include tech で隠れる。
- 判定済みかどうかは、従来どおり `judgments` に行があるかで決める。「該当なし」の記事も判定済みになり、再判定しない。

## 理由・検討した代替案

- **保存せず未判定のまま残す案は採らない。** 該当なしの記事が多数派なので、毎時同じ記事を選んで Jev を呼び直し、1 回の上限（20 件）を使い切る。他の記事に判定が届かなくなる（TASK-32 の飢餓を悪化させる）。同じ入力に同じ答えが返るので、再試行しても結果は変わらない。
- 保存すると、記事一覧の SQL（`MAX(score)` の行を記事のジャンルとする）、スキーマ、画面を変えずに済む。

## 影響

- ユーザーが「該当なし」という名前のジャンルを作ると区別できない。問題になったら、入力側で予約語として弾く。
- 記事一覧は `MAX(score)` の行を記事のジャンルとするので、「該当なし」とジャンルが同点のときどちらになるかは SQLite の実装次第になる（ジャンル同士の同点と同じ）。確率が完全に一致することは稀なので、問題になったら `ROW_NUMBER()` で順位の付け方を明示する。
- この決定より前に保存された行は「該当なし」を持たず、低いジャンルのまま残る。移行は行わない。直すときは、その記事の `judgments` を消して再判定させる。
