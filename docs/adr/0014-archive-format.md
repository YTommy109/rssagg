# ADR-0014: アーカイブは本文を Markdown で R2 に保存する

- 状態: 採用
- 日付: 2026-10-19

## 背景

「後で読む」に入れた記事の全文を、元のサイトが消えても読めるように R2 へ残す（[ADR-0003](0003-d1-r2-vectorize.md)、TASK-19）。形式は ADR-0003 で未決とした。比べる観点は次の 4 つ。

- 元のサイトが消えても読めるか（自己完結しているか）
- Cloudflare 上で作れるか、費用と制約はどうか
- 保存一覧から開いて読めるか（TASK-19 の受け入れ条件）。新しい依存が要るか
- ローカル（`wrangler dev`、vitest）で試せるか。ADR-0007 は remote を使わない

## 決定

- 記事の**本文を Markdown（UTF-8）で保存**する。R2 のオブジェクトキーを `saved.archive_key` に入れる。
- **画像と体裁は保存しない。** 画像は元の URL への参照のまま残るので、元のサイトが消えると画像は失われ、テキストだけが読める。
- 閲覧は、アプリが Markdown を HTML にして Access の背後から返す。Markdown に混じる生の HTML は無効にし、第三者のコンテンツをそのまま描画しない。
- 取得と本文の抽出・Markdown 化の方法は決めない。TASK-19 で試作して選ぶ。候補は、Worker での取得 + 本文抽出ライブラリ、Workers AI の `toMarkdown`、Browser Run の `/markdown`。

## 理由・検討した代替案

| 形式 | 自己完結 | Cloudflare で作る | 閲覧に新しい依存 | ローカルで試す |
| --- | --- | --- | --- | --- |
| **Markdown** | テキストのみ（画像は参照） | 取得 + 抽出なら Worker だけで足りる | Markdown → HTML の変換が要る | 抽出ライブラリなら可 |
| PDF | 画像・体裁ごと保存 | Browser Run の `/pdf`（ブラウザ時間を使う） | 不要（ブラウザが表示） | `quickAction` は `wrangler dev` では使えない（`--remote` か `remote: true`） |
| `.webarchive` | 画像・体裁ごと保存 | 作れない（下記） | 開けるのは Safari と macOS が中心 | — |
| HTML 単体（資源を埋め込む） | 画像・体裁ごと保存 | 資源の収集と埋め込みを自作する | 第三者の HTML なので XSS の対策が要る | 可 |

- **先例**: Instapaper は本文を自前で保持しつつ、画像は元のサイトの URL を参照しているようだ（保存した記事の画像が note.com の配信元 `assets.st-note.com` の URL だった、という利用者の観察。公式の説明は確認できていない。標本は 1 件）。本文だけを残し、画像は参照のままにする構成として、この決定と同じ。
- **採る理由**: このツールは記事を読むためのもので、画像の保存まで求める用途は想定していない。Markdown は小さく、R2 の費用がほぼ増えず、本文を後で検索にも使える。ADR-0006 の HTML 配信とも合う。抽出を Worker で行えば、ブラウザ時間の費用も remote 前提のテストも避けられる。
- **PDF**: 画像まで確実に残るのが利点だが、ブラウザ時間（無料枠は 1 日 10 分、有料は月 10 時間込み）を使い、1 記事あたりの所要時間は未計測。ローカルで試せない。スマートフォンでの読みにくさもある。画像の欠落が実際に困ったら、新しい ADR で追加する。
- **`.webarchive`**: Safari の形式（バイナリの plist に資源を詰める）。Browser Run は Chromium で、`/snapshot` の出力形式は content・screenshot・markdown・accessibilityTree の 4 つで、`.webarchive` は無い。Worker で資源を集めて plist を組むのは手間が大きく、閲覧も Apple 環境に偏る。
- **HTML 単体**: 資源の埋め込みを自作する費用と、第三者の HTML を配る危険に見合わない。

## 影響

- 画像は残らない。元のサイトが消えると、記事内の画像は表示できなくなる。これが困る記事が増えたら見直す。
- TASK-19 は、Markdown を HTML にする仕組み（生の HTML を通さないこと）と、取得・抽出の方法を選ぶ必要がある。選んだ方法は ADR か TASK-19 の記録に残す。
- 抽出に Workers AI を使う場合は、AI バインディングが要る。ADR-0011 で埋め込みを不採用にしたので、新たに足すことになる。
- 未検証: 本文抽出ライブラリが Workers 上で動くか。`toMarkdown` と `/markdown` の本文抽出の質（ナビや広告が混ざるか）。Browser Run の 1 リクエストあたりのブラウザ時間。
